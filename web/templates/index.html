About File Integrity Checking

Fundamental concepts, cryptographic principles, security guarantees, and tool limitations.

What is File Integrity?

File integrity refers to the assurance that digital files remain intact, genuine, and unaltered from their original trusted state. In cybersecurity, unauthorized changes can occur due to malicious tampering (ransomware, backdoors, trojans), transmission corruption, or accidental disk faults.

Integrity is the "I" in the foundational CIA Triad (Confidentiality, Integrity, Availability).

What is SHA-256?

Secure Hash Algorithm 256-bit (SHA-256) is a member of the NIST-standardized SHA-2 family. It maps arbitrary data of any size into a fixed-length 256-bit (64-character hexadecimal) cryptographic digest.

  • Deterministic: The same file content always produces the exact same 64-character hash.
  • Avalanche Effect: Changing just 1 bit in a multi-gigabyte file completely randomizes the output hash digest.
  • Collision Resistant: Computationally impossible to find two different files that produce the same digest.

Hashing vs Encryption

A common misconception in cybersecurity is confusing cryptographic hashing with encryption.

Hashing (One-Way)

Irreversible mathematical transformation. You cannot recover the original file from the hash digest. Used for integrity verification.

Encryption (Two-Way)

Reversible transformation requiring a secret key to decrypt back to plaintext. Used for confidentiality.

Scope & Limitations

Understanding what this utility does and does not do is essential for practical security posture:

  • MATCHED != Malware-Free: If you baseline a malicious file, a MATCHED check only confirms the file is identical to that malicious baseline.
  • Local Scope: Baselines and verification histories are kept strictly in a local SQLite file (integrity_checker.db).
  • Zero External Transmission: Your files and hashes are never sent across a network or uploaded to cloud services.
